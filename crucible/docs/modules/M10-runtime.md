# M10 `runtime` — running policies reliably

**Status: core built (2026-10-09); audited 2026-10-12 (`docs/audit/2026-10-12/M10-runtime.md`); exit gate in progress.**
- **Audit:** 17 reproduced defects fixed. A policy could turn its own failure into a mask (a broken `.git`, an
  unreadable file, a background job during perf grading, a raised exception); a credential echoed by a provider reached
  14 record and trace files; one harness exception aborted a run; retries re-ran the agent; resume worked only once and
  charged restored calls twice.
- **B.5 injections ✅:** all 8 harness and infra classes are injected and masked (CPU in `tests/unit/test_runtime.py`, Linux-container classes in `tests/redteam/test_runtime_docker.py`).
- **Policy controls ✅:** they are scored, not masked.
- **Historical run reproduction ⏳:** R1 (re-grade) ✅. R3 (live mini-swe-agent through Harbor): the harness, the patch seam and the gate script are built (M10 lab audit 2026-10-15 R-1); the live run is pending. R2 (replay) is pending.
- **Lab audit R-1 (2026-10-15):** installed Harbor agents run as a harness with evidence-based blame (a non-policy blame needs proxy or host evidence; an agent's own claims never mask its 0), the capture key revoked when the agent phase ends, spend settled from the capture, and an OpenEnv-ported capture-vs-ATIF reconcile on every record. The A2A harness gets the same evidence rule, agent liveness, a limit policy and spend.
- **Lab audit R-2 (2026-10-15):** no in-place Harbor grade while a policy process can run (P23). `HarborInPlaceTask.open` records a process baseline from the host before the policy, an installed agent or the grader capture runs; every in-place grade (single-step, each multi-step step, and R-1's shared-verifier seam) first kills every process started after it, confirms with the host's `docker top` taken with the container paused (review round 1: a fork-and-die chain is listed too), and writes `<workdir>/../verifier/quiesce.json` (`{before, killed, survivors, rounds, method, verdict, ...}`). Only a clean receipt reaches the reset and Harbor's verifier. A process still listed after the bounded rounds is `crucible:policy_misbehavior` (scored 0, flag `policy_process_survived`); one killed and confirmed gone is recorded under `killed`, not blamed, and flagged `policy_process_killed` (non-scoring: bench `flag_rules`, a passing attempt keeps its reward but counts in bench's hack `rate` as a flagged pass, studio skips it as flagged; review round 2: a multi-step step grade's flags reach the rollout, `NativeHarness.run` merges them with the trace's rule flags, and they ride a report `_liveness` replaced). This reading of Acceptance 1 (which asks for `policy_misbehavior` for a killable setsid writer) is an R-2 amendment the user chose on 2026-10-17. A host that cannot list or drive the container, or a helper exec the daemon never started, masks `crucible:backend_error`; only respawned children of a pristine service, or only uninterruptible processes, end the attempt as a non-retryable `crucible:backend_error` of unknown blame; a later multi-step step's `setup.sh` that left a process running ends it as a non-retryable `crucible:harness_unsupported` of unknown blame (review round 2: a root policy can make that setup start one; review round 3: a task whose later setup leaves a process running in a pristine preflight container, before any policy, is refused at `HarborMultiStepTask.open` with harness blame, so an honest task never counts toward the 5% unknown-blame stop). Review round 3: the survivor flag also rides a report `_liveness` replaced; a pause refused while a target turned D ends the quiesce `uninterruptible` (`pause_refused`), never the policy's. Environments the host cannot list (non-Docker providers) are refused in place as `crucible:harness_unsupported`.

## What it is

| Piece | What | Built on |
|---|---|---|
| `keys.py` | `SampleKey(task, world, policy, harness, sample_idx, seed, tier)`. Seeds are derived from the run seed and the key; attempt ids are `<sample>-a<N>`; the run identity is a hash of the spec minus cosmetic fields | FineEnvs identity |
| `infra.py` | Failure normalization at every boundary (Harbor exception names, MiMo categories, provider errors) into kinds with a **blame**. `RetryRule` never retries policy blame; `LimitPolicy` turns limits into scored stops; masked-aware `mean_reward`, `coverage`, unbiased grouped `pass_at_k`; `Health` stop rules; `classify_verifier` | NeMo-Gym `failure_kinds`/`rollout_health`; verifiers errors and `RetryRule`; Karotte limits |
| `journal.py` | `run.json` identity (a mismatch refuses to resume), fsynced `journal.jsonl`, `results.jsonl` (terminal), `failures.jsonl` (masked, never read by metrics), atomic `record.json` per attempt; aborted attempt dirs are kept as evidence | Repo2RLEnv `EventJournal`; NeMo-Gym sidecars, torn-tail repair |
| `budget.py` | SQLite reserve/settle ledger with caps; reservations left by a crash become *uncertain* spend; uncertain spend has its own tolerance | Repo2RLEnv `campaigns/budget.py` |
| `run.py` | `RunSpec` → plan → bounded-concurrency dispatch → reserve → harness → settle → record → retry. Credits exhausted → stop, resumable | agentenv `eval run --k` (shape) |
| `harness/native.py` | A World episode with an in-process policy: masked episode → failure; `task.broken()` → `crucible:agent_broke_env` (policy); limits → truncated and scored; grading → `classify_verifier`; cleanup never overrides a result | — |
| `harness/workspace.py` | Collects the agent's work as a patch (tolerant or legacy hook). An empty patch from a changed tree → `crucible:empty_collection`, workspace preserved; the retry re-collects only | our `run_agent.sh` collect fix |
| `collect.py` | `collect`, `tree_changed`, `classify` | — |
| `remote.py` | Sentinel control channel (`crucible:harness_self_kill`), pidfile kills, self-matching `pkill`/`pgrep` lint | B.5 row 8 |
| `gpu.py` | `GpuHost` (`--runtime=nvidia`), `preflight` (PID 1 init check → `crucible:zombie_wait`; GPU arch) | B.5 row 4 |
| `verify/stage.py` `docker_grade` | Pins the image digest (`expected_image` mismatch → masked `stale image` before grading); named, labelled container; timeout → `docker rm -f` + masked `verifier_timeout`; no reward file → masked `no_reward_json` | Harbor verifier behaviour |
| `perf_guard.py` | One perf grade per host (lock); host check before the grade (foreign GPU compute memory, GPU utilization, load per core); waits, then `node_contention` (masked) if never quiet | grader-side `LoadGuard`; Harbor regrade |
| `trajectories.py` | ATIF v1.8 per actor joined to model calls (`call_id`, `llm_call_count`, per-call `Metrics` with token ids/logprobs), `no_action` steps for blank calls, `FinalMetrics`; `align` sets `StepRow.atif_step_id`/`call_id`; the capture cross-check is `interop/harbor/reconcile.py` (M10 lab audit R-1: `cross_check` needed equal call counts, had no caller, and is removed) | Harbor ATIF models (DEPEND) |
| `interop/harbor/reconcile.py` + `Runner._rollout` | The agent's ATIF against the proxy's captured calls, call by call (completion tokens; counts only when a call has none): auxiliary calls demoted (`aux_call_ids`) only with ≥ 50% ATIF coverage; synthetic API-error, proxy limit-stop and `llm_call_count == 0` steps left out; missing calls, mismatches and subagents FATAL. Every record carries `meta.reconcile` (and `meta.agent`); a FATAL report masks a train rollout as `crucible:capture_incomplete` (unknown blame, never retried) and flags the rollout `reconcile_fatal` in both modes | PORT: OpenEnv `harbor/atif.py` (BSD-3-Clause, 55347f62e2) |
| `agent_evidence.py` | The classification table for agents Crucible does not drive (Harbor installed, A2A): what the capture proxy saw last (`read_upstream_evidence`: 5xx/408/429, a connect error or a dropped stream → `provider_unavailable`; 402 or a quota answer → `crucible:credits_exhausted`; 401/403/404 → `crucible:harness_unsupported`), what the host saw (container gone, A2A agent unreachable) and how the agent ended → a stop or a typed failure. The agent's own claims (Harbor's regex error classes, mini-swe-agent exit statuses, A2A self-reports) never mask its 0: a non-zero exit with a healthy proxy is scored; an installed agent that ends abnormally or at the deadline before any recorded upstream exchange is `unknown`; an unconfirmed infra claim is `unknown`. The session log is writable by the agent's commands (they hold the capture key), so an upstream verdict that blames someone else counts only when Crucible's own probe of the upstream (`confirm_upstream`, `CaptureProxy.probe`) answers the same, else `unknown`; the probe asks the configured model on the configured dialect (never an A2A policy's own route), is skipped for an infra verdict after more than 30 forwarded calls running in the last minute, or while any of the session's calls is still in flight upstream (the harnesses wait for them first: the failure may be the session's own load; a connection the upstream refused is probed at any rate), and waits out a 429's Retry-After. Only evidenced limit stops (Crucible's deadline, the proxy's call cap) can be masked or penalized, and both yield to the proxy's failure evidence first (a cap burned by failed calls is the provider's); an upstream overflow answer is recorded, not evidenced. `capture_spend` (every forwarded row, retries included; usage-less and cut calls booked as an uncertain bound) with `self_hosted_apis` (self-hosted per upstream), `host_secret_names` and `leaked_host_secrets` | PATTERN: AReaL proxy workflow (the proxy's observation overrides the agent's report), agentenv `AgentUnreachableError`, mini-swe-agent exit statuses |
| `interop/harbor/agent_harness.py` | `HarborAgentHarness`: a Harbor installed agent class driven directly in the World the task adapter opened, never Harbor `Trial`/`Job` (Trial relabels any TimeoutError in `agent.run`, Job cancels sibling trials on one create error, a retry rmtrees the trial). Per attempt: a capture-proxy session with a call cap; endpoint variables built from scratch (capture key, proxy URL) and scoped to setup and run, every other host credential variable blanked in the agent's commands; a host credential in the agent's view refuses the attempt (a constructor's missing config file too, never retried); setup under its own deadline before the restricted agent phase (`crucible:backend_error`, never the policy's); `agent.run` under Crucible's deadline; the key revoked when the phase ends; the agent's processes stopped: on the patch seam a non-root agent user's outside the container's init session, else the phase's process cohort by start time (both as root in `/`, reading `/proc` with shell builtins: no procps; zombies skipped; killed and looked for again up to five times; the children a service older than the phase forks are killed too but reported as `respawned`, never the policy's; a process in uninterruptible sleep is waited for, then reported as `uninterruptible`; a stop that cannot list the processes exits non-zero). The stop still runs under the image's `bash` and calls `sleep`, which a root policy can replace, so it is trusted only when it prints its own report: one that never reports is run again, then is the policy's when its shell started and was stopped while a fresh root shell answers or when `bash` is gone, else unknown. The collect is refused when processes of the phase survive the stop (`crucible:policy_misbehavior`), when only uninterruptible ones do (masked, never retried) or, for an unfinished run, when the stop stalled or broke in a live container (`crucible:agent_broke_env`) or failed (masked `crucible:backend_error`, unknown blame when it never reported); in place the agent program's own tree, then the grade's host-side quiesce (lab audit R-2) kills every other process started after `open`, so a service the agent left running for the tests fails the grade (R-2's accepted trade-off; `agent_run.json` records the stop's `scope`); the agent's logs copied to a host-only `agent_logs` that follows no link before anything reads them or Harbor's converter writes; evidence → `agent_evidence`; records `agent_run.json`, `calls.json`, `agent_trajectory.atif.json`, `reconcile.json`; `meta.agent` (agent, digest, Harbor version, model, session) on every record, refusals included. Id `harbor:<agent>@<version>#<digest>` over the agent name (full import path), agent kwargs, limits, limit policy, model, Harbor version and endpoint variables. Coded against Harbor 0.24.0 behind narrow adapters (the lock pins 0.23.0); the installed version is on every record | DEPEND: Harbor installed agents and environments |
| `interop/harbor/patch_task.py` | `HarborPatchTask`: the separate-verifier patch seam (task02). The agent works in a World on the task image; the task's `[[verifier.collect]]` hooks produce `/logs/artifacts/model.patch` (read through the container as root: a regular, non-symlink file within a size cap; never a host path the container controls; framed and classified by the verdict the in-container shell prints, since Harbor's exec merges stderr into stdout and returns docker or ssh failures as exit codes); the World is closed; `HarborDirTask.grade_patch` grades it in a fresh container. A masked grade is re-graded from the stored patch (with the prior attempt's evidence), never by re-running the agent. Each hook is framed the same way (a start marker and the hook's own `rc` verdict), and the read runs in `/`. A collect hook whose verdict is non-zero or that outlives its deadline, or a read that outlives its deadline or frames something that is not the patch, in a live container is the agent's (`crucible:agent_broke_env`); so is a hook or read whose shell was killed or could not start in the container's state (`bash` or the working directory removed) while a fresh root shell answers, since a root policy controls every binary in the container and can forge any text the exec returns; a symlink or special file at the patch path is `crucible:policy_misbehavior`; a read or hook exec that keeps raising fast (host side) masks as infrastructure, and one that returns without the shell's report with nothing showing whose masks with unknown blame, neither retried; a lost container masks | Harbor's separate-verifier hand-off (trial.py:1443-1510) |
| `interop/harbor/quiesce.py` (lab audit R-2) | The host-side quiesce before every in-place grade (`HarborInPlaceTask._verify`, before `_reset_shared_dirs`). Baseline at `open`: PID 1's host pid (`docker inspect`), a start mark read by a root `sh` with builtins, and the host's `docker top -eo pid,ppid,stat,nlwp,etimes,args` listing (Harbor's keep-alive and image services: spared; `-e`: moby's fallback without `-q` would otherwise drop non-root processes). At the grade: every other process but a single-threaded zombie is a target (a zombie leader with live threads is not spared); a builtin-only `sh` helper (`docker exec -u 0 -w /`, forks nothing) SIGKILLs everything started at or after the mark except PID 1 and itself; the host lists again, up to 5 rounds, then waits while only state-D processes remain. Every judging listing is taken with the container frozen (`docker pause`, `docker top`, `docker unpause`; a pause event no longer reads as "stopped from outside"), so a fork-and-die chain is listed every round and ends a survivor; a target in state D (its leader's STAT or, review round 3, any thread's, from a per-thread `docker top -eLo` taken when a multi-threaded target's leader does not read D) is never paused for (the freezer cannot take it: that round is judged unfrozen, and an unfrozen listing never ends `clean`); a pause refused while a target turned D ends the quiesce at once `uninterruptible` (`pause_refused`: the cgroup may still be freezing, so nothing after it can blame the policy), and an unpause follows every pause request, a failed or timed-out one included (review round 2). Only the host listing decides (a root policy controls every in-container binary); the helper's rc and output are recorded only, and a helper exec that failed fast with no `exec_start` in the daemon's events never reached the container (masked). A pristine pid counts as pristine only while its start time (from `etimes`) is not later (pid reuse). The receipt `verifier/quiesce.json` lists `before`, `killed`, `survivors`, `setup` and `leftovers` (plus `unfrozen` and `pause_refused`) as `{pid, ppid, stat, nlwp, etimes, args}` (host pids). Through `HarborBackend.docker`, so `DOCKER_HOST=ssh://` works; a busybox `ps` on the daemon host, or a daemon that cannot pause, fails closed (masked). Multi-step: the baseline is taken again after the first step's setup only; a later step's setup is listed before and after, and what it started is killed before the step's grade, which then masks as `crucible:harness_unsupported` (`setup_service`, unknown blame, review round 2; review round 3: `open` first runs every step's setup once in a pristine container and refuses, with harness blame, a task whose later setup leaves a process running there); after a clean step grade the next step is listed before its setup, and what that grade left running and its descendants (`leftovers`, review round 3) are killed at the next grade, never flagged (a descendant of a pristine service stays flagged). Residuals: a pristine service the policy took over, a pristine service the policy sets respawning (masked with unknown blame), a policy that makes a later step's setup start a process (a replaced tool it runs) or keeps a process of its own in state D (both masked with unknown blame, never retried), and a process the policy's code under test starts during the verifier | PATTERN: karotte confirm-and-score (MIT), NeMo-Gym receipt before verify (Apache-2.0) |
