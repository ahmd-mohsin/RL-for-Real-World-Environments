# h3 task (held out): a hint and two environment bugs fixed, now kept for the benchmark

**Task:** `db-node-h3-a6cd4654` (Ahmed; same id, rebuilt by Uzair 2026-10-23)
**Result:** kept for the benchmark

## What the task is

The agent gets **h3** (a small Node.js web framework) with two real bug fixes undone, plus a bug report written like a
message from a user. It has **300 tool calls** to fix both. Hidden tests check each bug.

This is a **held-out (benchmark)** task: kept when the student passes **under 30%** of attempts and a strong model can
solve it. Held-out tasks are never made easier; only real defects are fixed.

| # | Bug, as the user sees it |
|---|---|
| m01 | When a classic Node handler streams a response and the stream fails, the app's error hook is never called |
| m02 | With the error-handling middleware, that failed stream is wrongly handed to the middleware (needs m01) |

## Before

## The defects we found

1. **A hint in the start code.** h3's `CHANGELOG.md` described both fixes almost word for word ("Call `onError` for stream
   errors in Node.js handlers", "Pass through handled responses in `onError`").
2. **The environment broke on our machine.** The Node setup ran `cd` on the workspace path without quotes, so on a path
   with spaces every attempt failed before starting.
3. **The agent could not run its tests.** The workspace is reset once more just before the agent starts, and that reset
   removed the link to the installed dependencies. Every attempt got "vitest not found"; agents then tried `pnpm install`,
   which the rules forbid, so even a correct solution lost its full pass. This likely affected Ahmed's measurement too.

## What we changed

1. **Pipeline:** changelog entries that name an undone fix are removed from the start code (all tasks, all repos).
2. **Pipeline:** the Node setup quotes the path, and runs again after every reset (all Node tasks).
3. **The task itself is unchanged:** same bugs, same tests, Ahmed's report word for word.
