# M13 audit 05: horizontal and vertical scaling

**Date:** 2026-10-10.

**Method.** Every claim below comes from code read in this checkout, or from the article with a line number. Nothing is inferred from documentation alone. "Not found" means targeted searches came back empty: absence is likely, not proven.

**Path prefixes:**
- `F/` = `RL-Environments/06-frameworks-and-env-code/`
- `AE/` = `agentenv-framework/`
- `ART` = `RL-Environments/07-articles/qingkeai-2026-agentic-rl-infra.md`
- Crucible paths are relative to `crucible/`.

**Scope.**
- *Horizontal scale:* thousands of concurrent rollouts across many hosts, many inference engines, multi-node trainers.
- *Vertical scale:* 1M-token trajectories, thousands of tool calls, multi-hour episodes.

## 0. Headline findings

1. **The rollout plane runs in one process.**
   - `Runtime` runs one asyncio task per rollout on one event loop (`src/crucible/train/runtime.py:327-332`).
   - Environments run inline or on `EnvWorkerPool` *threads* in the same process (`train/envpool.py:30-97`).
   - No rollout, environment or episode can run on another host. Crucible has no Ray, ZMQ or RPC client anywhere in `src/crucible`.
2. **The control-plane hot path is O(N) per call and grows without bound.**
   - `DataPool.untrained()` scans every tag ever created (`train/pool.py:155-158`).
   - `Scheduler.admit` calls it once per admitted group (`train/scheduler.py:97-119`), which makes admission O(N²).
   - Tags, values, `Runtime.tasks` and `RunReport.trained_records` are never freed (`pool.py:115-149`, `runtime.py:332,359`).
   - At 32k concurrent rollouts (LongCat, `ART:132`) this stalls the event loop that every model call goes through.
3. **A training run cannot be resumed.**
   - The M12 runtime keeps prompt sources as in-memory lists (`runtime.py:138-140`).
   - No trainer, optimizer, scheduler or pool state is saved; the only `torch.save` is the offload path (`trainer.py:101`).
   - The resumable M10 `RunJournal` (`runtime/journal.py`) and the episode `Checkpointer` (`runtime/checkpoint.py`) are not wired into M12.
4. **There is no engine health handling.**
   - `EnginePool.route` is crc32-sticky but silently falls back to the least-loaded engine (`engine.py:104-108`). The fallback breaks KV affinity.
   - There are no health checks, so a dead engine is never removed.
   - Its HTTP errors mask rollouts as `infra` (`runtime.py:106-116`) until the circuit breaker stops the run (`runtime.py:218-228`).
5. **Vertical scaling is built at the record level only.**
   - The M12 trainer turns every model call into its own item with its *full* reconstructed prompt (`trainer.py:144-165`). Forward cost is therefore quadratic in the number of turns.
   - `HFPolicy` materializes full fp32 logits `[B, L, V]` (`hf.py:48-84`).
   - Prefix sharing builds an L×L float mask (`hf.py:99-104`).
   - Episodes keep the full prompt of every call in memory and in checkpoints (`actors/policy.py:240-243`, `:172-177`).
   - The 1.1M-token long-horizon gate never exercised any of this: it replays actions with `ReplayLLM`, which records no tokens (`packs/_toy/.../longhorizon/gate.py:38`, `runtime/inject.py:114`).

**What the article adds** (production systems, not code):
- **LongCat DORA:** RolloutManager, SampleQueue and Trainer controllers on separate nodes over RPC. 32,000 concurrent environments on about 400 machines (`ART:132`). Per-sample remote workers with no batch barrier, 2–4× faster than synchronous training (`ART:184`).
- **GLM:** a central orchestrator with per-task rollout/reward microservices, 1k+ concurrent rollouts (`ART:128`). Heartbeat fault tolerance, removal of failed environments with group refill, 10k+ SWE environments (`ART:929`).
- **MiniMax:** Gateway Server + Data Pool that fully decouple generation from training (`ART:130`).
- **StepFun:** a "Session-Router" is named only; the article gives no mechanism (`ART:144,932`).
- **Kimi K3:** 1M-context RL, colocated, with weights and optimizer on NVMe and DRAM freed for an external KV pool (`ART:116`). Partial rollouts are paused with Firecracker sandbox pause/resume (133 ms / 49 ms) (`ART:168,876`).
- **DeepSeek DSec:** hundreds of thousands (V4) to millions (V4.1) of concurrent sandboxes with a custom placement engine (`ART:877`). Rollouts pause at any token boundary and resume from persisted state without re-prefill, via a token-level WAL (`ART:176,927`).
- **Long tail:** about 5% of samples take about 80% of generation (`ART:21`).

## 2. Horizontal scale: gaps and proposed architecture

### 2.1 Gaps, with evidence

| # | Gap | Evidence |
|---|---|---|
| H1 | Rollouts, environments and episodes are confined to one process. Thread workers share the GIL, and a CPU-bound World step (grading, SQLite) still serializes. | `envpool.py:30-36`; `runtime.py:155-158` |
| H2 | Control-plane cost is O(N) per call and O(N²) per admission. Memory is never released. | `pool.py:152-158`; `scheduler.py:97-119,212-216`; `runtime.py:327-332,359` |
| H3 | No run-level checkpoint/resume: sources, scheduler cursors, pool, trainer and optimizer state are all lost. | `runtime.py:138-140`; no save path in `train/` |
| H4 | Engines get no health checks, eviction or restart, and the router breaks affinity under load. The pool's version is the *minimum* over engines, so one stuck engine pins it. | `engine.py:104-137`; `vllm_http.py:41-44` (no retry) |
| H5 | No client for remote environments, although Crucible already serves two protocols. Crucible's NeMo-Gym server keeps sessions in an unbounded dict with no admission cap, expiry or `/health`. | `interop/nemo_gym/server.py:31-52` |
| H6 | Back-pressure is staleness-only. Nothing is KV-aware, there is no env-creation rate limit, and the engine `capacity` is advisory. | `scheduler.py:97-119`; `engine.py:104-118` |
| H7 | Observability is in-process only: no per-rollout trace spans and no engine metrics. | `runtime.py:461` (`StepLog` list) |
| H8 | The trainer scales out only as DDP replicas: every rank holds the whole model, so model size is bounded by one GPU. The NCCL weight sync is built but has only been tested over gloo on one host. | `trainer.py:307-325`; `weightsync.py` (§6a in M12 doc) |

### 2.2 Proposed architecture

```
                         ┌──────────── controller process (one per run) ────────────┐
 prompts ─► sources ───► │ Scheduler + DataPool tags (indexed, GC'd) + RunJournal    │◄── checkpoint commit
                         │ lease table (rid → worker, deadline) · publisher           │
                         └───┬───────────────────────────┬──────────────────────┬────┘
            dispatch(rid,lease) / heartbeat / result-ref  │ pause/abort/version  │ step(records)
                             ▼                            ▼                      ▼
        rollout workers (N processes, any host)   model gateway (1+ procs)   trainer (torchrun / bridge)
        run whole episodes: World or remote env ──► sticky-least-loaded,      DistributedTorchTrainer,
        server (NeMo-Gym / OpenEnv / agentenv);     health poll, version     or verl / prime-rl bridge
        write crucible.rollout/v1 values to store   stamping, abort/resume ──► engines (vLLM, N hosts)
```

The controller stays single. prime-rl's orchestrator, NeMo-RL's `SingleControllerActor` and GLM's orchestrator all show that one controller is enough once the hot path is O(1) and both episodes and model I/O run elsewhere. LongCat distributed its controllers only at 32k environments; we do not need that now.

**Ray-free versus Ray.**
- The Ray-free path follows prime-rl's model: OS processes, HTTP to the gateway, HTTP or ZMQ to the controller, SLURM/ssh launch (`F/infra-primeintellect-ai-prime-rl/src/prime_rl/entrypoints/rl.py:111-488`). It works on the lab node, which has Docker but no Kubernetes. It is the default.
- The Ray path adds placement and node-affinity scheduling.
- Both paths share one `Launcher` protocol, so no other code differs.

## 3. Vertical scale: gaps and proposals

### 3.1 Gaps, with evidence

| # | Gap | Evidence and size |
|---|---|---|
| V1 | **The trainer's forward cost is quadratic in turns.** `_items` emits one item per call with `full_prompts(r)[call]`. `micro_batches` never splits a sequence. | `trainer.py:144-165`; `batching.py:50-52`. The bridge path already chains a segment into one sequence (`bridges/common.py:51-84`), but the reference trainer does not. *Estimate:* xl-gate shape, 7,627 calls under a 128k budget with contexts growing to about 103k per segment, average about 50k → about 3.8×10⁸ forward tokens against about 1.1×10⁶ trajectory tokens, roughly 300× redundant compute. |
| V2 | **Logits are held in full.** `[B, L, V]` fp32, then `log_softmax` makes a second copy. | `hf.py:48-84`. At L = 128k and V = 151,936 (Qwen3) that is about 78 GB per copy, against the 5090's 32 GB. |
| V3 | **Prefix-sharing mask is L×L fp32.** | `hf.py:99-104`. About 65 GB at 128k. |
| V4 | **No sequence or context parallelism.** One causal segment must fit on one GPU. | Not in `train/`. Frameworks: verl `utils/ulysses.py`; SkyRL `ulysses/monkey_patch.py:53-130`; prime-rl `layers/ring_attn.py`, `ulysses_attn.py`; AReaL `models/fsdp/ulysses.py`; OpenRLHF `ring_attn_utils.py`; slime / NeMo-RL Megatron CP. |
| V5 | **Episode token capture is quadratic.** Every model call keeps its full `prompt_token_ids` (`world_env.py:58-63` → `policy.py:240-243`). Delta conversion happens only in `record.build` (`runtime/record.py:55-80`). `LLMToolPolicy.state_dict` writes all of `model_calls` into each `checkpoint.json` (`policy.py:172-177`). | Estimate for the xl shape: about 3.8×10⁸ token references, about 3 GB of list pointers per episode, and a checkpoint of similar order *per save*. Not seen in the gate because `ReplayLLM` returns no tokens. |
| V6 | **KV is thrown away at every publish.** `VLLMServerEngine.load_weights` always resets the prefix cache, and colocated `pause` sleeps at level 1, discarding KV (`vllm_http.py:83-105`). Every in-flight long context re-prefills after each publish. The cost is measured (`rollout/reprefill_tokens`, `runtime.py:173-181`) but never reduced. | Frameworks: keep-mode pause (SkyRL `PauseMode.KEEP`, prime-rl `/pause mode=keep`, OpenRLHF partial rollout); SkyRL `offload_kv_for_weight_sync`; NeMo-RL `recompute_kv_cache_after_weight_updates`. Article: DeepSeek's token-level WAL resumes without re-prefill (`ART:176`); Kimi uses an external KV pool (`ART:116`). |
| V7 | **No episode resume in M12.** M10 resumes a crashed episode from its checkpoint, re-prefilling one segment (`runtime/checkpoint.py:1-17`, `harness/native.py:84-120`). The M12 runtime masks the rollout instead (`runtime.py:201-206`). | A multi-hour episode lost at hour 3 is lost entirely. |
| V8 | **Memory bounds in the controller.** Every value (a 1M-token record means about 1M ids plus logprobs as Python objects) stays in `pool.values` and `trained_records` forever. | `pool.py:115-121`; `runtime.py:359`. rLLM offloads its buffer to NVMe (`trainer/buffer.py`). |
| V9 | **The compaction trigger uses a character estimate** (`approx_tokens` = chars/4, `policy.py:88-101`), while the engine's real prompt length is known exactly (`EngineLLM` holds the token count, `world_env.py:61`). At 1M tokens an estimate error of 10% or more can overflow `max_model_len`. | |
| V10 | **Long-tail pausing.** Token-mode resume exists (AReaL-style, `engine.py:46-51`, `runtime.py:173-178`). ROLL's agentic path has none (`policy_proxy.py:34-35`). But no idle World is paused or snapshotted to oversubscribe env memory, as Kimi does (`ART:168,876`). | |

### 3.2 Proposals

| # | Change | Reuse | Acceptance test | Priority / effort |
|---|---|---|---|---|
| V1 | **Segment-level training items.** One causal sequence per (actor, segment), with completions masked in and observations masked out. Reuse `bridges.common.flatten` inside `TorchTrainer._items`. Per-call advantages and version spans map to token ranges (`call_spans` already exist). | Depend: own `flatten`. Pattern: verl `tool_agent_loop.py` response_mask; slime `TrajectoryManager`. | Loss and gradients equal the per-call path within 1e-6 (TinyPolicy, tiny HF). On a synthetic 2,000-call segment, forward tokens ≤ 1.05× segment tokens. `train/forward_tokens` is logged. | **P0 / S–M** |
| V2 | **Chunked fused LM-head logprobs.** Online logsumexp over vocab chunks with an fp32 head, never materializing `[L, V]`. Top-p renormalization runs per chunk over the candidate ids. | Port: prime-rl `trainer/models/layers/lm_head.py:40-120`; AReaL `utils/functional/vocab_parallel.py:42-82`. | Equal to `batch_token_logprobs` within 1e-5 (with and without candidates). On the 5090, Qwen3-0.6B trains a 32k-token segment with peak memory ≤ 28 GB (`torch.cuda.max_memory_allocated`); today's path OOMs at that length. | **P0 / M** |
| V3 | **Prefix sharing via varlen attention** (FlashAttention `cu_seqlens` or a FlexAttention block mask) instead of a dense 4D mask. | Pattern: slime THD `PackedSeqParams`; OpenRLHF `packing_samples`. | Same equality test as checklist #50. Mask memory is O(L) at 64k. | **P1 / M** |
| V4 | **Sequence parallelism (Ulysses)** in the native trainer for segments up to the compaction budget (128k). 1M-token *single* segments go through the bridges (Megatron CP via verl or slime-style bridges); we do not build ring attention ourselves. | Port: verl `utils/ulysses.py` / SkyRL monkey patch. Depend: `ring_flash_attn` only if needed. | SP=2 over gloo with two CPU processes equals SP=1 within 1e-5. On the 5090, two processes sharing one GPU (gloo on CUDA tensors) for correctness only. Throughput needs multiple GPUs (deferred; note it in the run record). | **P1 / L** |
| V5 | **Linear capture.** `EngineLLM` emits delta tokens at capture time (it already holds `_prev_ids`). Calls stream to `calls.jsonl` (listed in long-horizon.md "Remaining"). Checkpoints store offsets into that file, not token lists. | Pattern: rLLM gateway `TokenAccumulator`; AReaL `InteractionCache` parent chains. | A 1M-token synthetic episode with real token records (ScriptedEngine through `EngineLLM`, 5,000 calls, compaction at 128k): peak RSS ≤ 4× the raw trajectory bytes; checkpoint size grows linearly; records are identical to today's `build`. | **P0 / S** |
| V6 | **KV policy at publish** as an explicit, recorded knob: `kv_after_publish = reset` (today; exact) \| `keep_stale` (keep-mode pause; the stale-KV tokens are marked in `version_spans` so corrections see them) \| `offload_recompute`. | Depend: vLLM `/pause?mode=keep`. Pattern: SkyRL, NeMo-RL. | On the 5090, a 64k-context rollout pool with publish every step: `reprefill_tokens` per publish drops ≥ 90% under `keep_stale`, and `rollout_probs_diff` is reported separately for the stale spans. | **P1 / M** |
| V7 | **Episode resume in M12.** Workers checkpoint Worlds every k steps (M10 `Checkpointer`). Lease expiry or a crash resumes from the checkpoint, not by masking. The record carries `resumed_from` (already defined). | Depend: M10 checkpoint. Pattern: NeMo-RL rollout recovery; Kimi sandbox pause/resume. | Kill a worker at step 3,000 of a long-horizon toy episode inside M12: the episode completes, re-prefills at most one segment, and its reward equals an uninterrupted replay. | **P0 / M** (with D) |
| V8 | **Values off the controller** (store by ref; tag-only scheduling, checklist #39), with NVMe spill. | Pattern: MiMo TransferQueue (cited in `pool.py`); rLLM NVMe buffer. | 1,000 buffered 1M-token records: controller RSS < 2 GB. Values are fetched only for selected groups. | **P1 / S–M** |
| V9 | **Exact token budget.** The compaction trigger uses the codec's prompt length when an engine LLM is in use. | Own `chat.py`. | Contexts never exceed the budget by more than one turn on 100 long-horizon seeds with a real tokenizer. | **P1 / S** |
| V10 | **Pause idle Worlds.** A World waiting on a long-tail rollout is snapshotted and released, then restored at its next turn, to oversubscribe env memory. | Depend: M10 `World.snapshot/restore`. Pattern: Kimi (`ART:168,876`). | 2,000 rollouts on 256 env slots complete with identical records. | **P2 / M** |

## 4. Order of work

- **P0:** A, B, C, D (Ray-free), V1, V2, V5, V7. These take Crucible from one process with a replayed 1.1M-token episode to many hosts with 1M tokens trained.
- **P1:** E, F, G, H, V3, V4, V6, V8, V9.
- **P2:** I (sharded training through the bridges), V10.

V1, V2, V5 and A are scale defects in code that already ships (trainer, capture, pool contract), not new features. Under the "structural findings: act now" rule they belong in M12 now, with DESIGN.md §10.3–10.4 updated in the same commit.
