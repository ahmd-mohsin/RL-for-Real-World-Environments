## Structural problems (fix first)

1. **M4 reliability is circular.**
   - The coding mapper labels a review comment a `rejection` when the code was *not* changed
     (`CR/packs/coding/src/crucible_pack_coding/signals.py:85-92`).
   - `verdict()` marks a negative signal "contradicted" when `acted_on is False` and the outcome is good
     (`CR/src/crucible/signals/reliability.py:54-60`). So every rejection on a merged PR is contradicted by definition:
     `rejection` scores 0/21.
   - `correction`, `suggestion_accepted` and `revert` are "confirmed by construction" (`reliability.py:26,52-53`), which
     gives 0.987.
   - **Most of the reliability that M6 consumes comes from how the mapper labels, not from evidence.**
2. **Provenance (engineering rule 4) is broken in M3 and M4.**
   - `TraceSource` has no raw-payload hash and no connector version (`core/schema/trace.py:22-27`).
   - `ingest()` drops the `RawRecord` (`connectors/base.py:45-54`), and `core/prov.py` is unused here.
   - Milestone `Provenance` has no input hashes (`workflow/milestones/mine.py:128`).
3. **Signal-derived milestones are dead code.** `from_signals` is never called. Its check is `exists(path)`, which is
   already true at base, so the `non_trivial` filter would drop it anyway (`mine.py:195-209`, `filters.py:38-39`). The M5
   doc still lists "Signal" as a mining source.
4. **The spec and the code disagree.**
   - `workflow/__init__.py:7` and ARCHITECTURE M5 name `fidelity.py`, `segment.py` and `states`; none of them exist.
   - The held-out next-milestone accuracy (ARCHITECTURE §1.4) is not implemented.
   - M4's `labels.py` is missing.
5. **One episode becomes several traces.** Trace ids are keyed by source (`chat:`, `capture:`, `<family>:<case>`), so the
   same episode ingested through ATIF and through capture becomes two traces. Reliability statistics then double-count it.
