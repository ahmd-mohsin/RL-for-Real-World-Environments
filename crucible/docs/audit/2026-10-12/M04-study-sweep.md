# M4 study: sweep of every locally cloned RL environment, harness and trainer

Read-only, 2026-10-12. The three focused studies (`M04-study-mapping.md`, `M04-study-attribution.md`,
`M04-study-reliability.md`) read the frameworks M4's spec names. At the user's request ("read all the rl environments
cloned locally"), four more agents swept every remaining local repo and dataset for anything M4 could use:
- every repo in `RL-Environments/06-frameworks-and-env-code/` (30), including a deeper M4 read of the trainers the
  focused studies only skimmed;
- `agentenv-framework/` and `deepswe/`;
- the 33 dataset folders in `RL-Environments/08-hf-rl-env-datasets/`;
- the code and docs of `RL-Environments/01-lab-releases/xiaomi-mimo-v2.6-rl-oss` (weights skipped).

Headline: no repo or dataset turns real later evidence (reverts, hotfixes, reopened tickets, review comments, real PR CI
history) into typed, step-attributed signals, and none measures annotator agreement. What they offer is patterns:
"cannot judge" kept apart from 0, infra errors excluded from credit, cross-run flake rates, evidence-bound labels,
typed failure categories, and label-noise-aware losses that can consume M4's reliability. Defects the sweeps found
in Crucible are folded into the audit report (`M04-signals.md`) with their ids (H = harness sweep, T = trainers, C =
collections); the parts below are the agents' reports as written.

## M4 `signals` sweep: collections (fineenvs, HF spaces, repo2rlenv, prime-environments, autoresearch, 08 datasets)

Date: 2026-10-12. Read-only. `REF` = `RL-Environments/06-frameworks-and-env-code/`. `DS` = `RL-Environments/08-hf-rl-env-datasets/`.

How I searched: I read the README and docs of every repo and dataset, then grepped the code for rubric, judge, flaky, rerun, retry, FAIL_TO_PASS, agreement, kappa, calibration, majority, preference, human, rating, review, revert, merge, blame, credit, per-turn, pivot, partial, held-out, split, noise and confidence. Sub-sweeps of prime-environments (109 envs), fineenvs plus the three HF spaces, and the 33 datasets were spot-checked against source. Every citation in sections 2 and 3 was opened and confirmed. Two citation paths from the sub-sweeps were wrong and are corrected here: the watercolour files live under `02-watercolour/envs/watercolour/core/`.

**Headline.** No repo or dataset turns real post-hoc workflow evidence into labels, meaning reverts, hotfixes, reopened tickets, review comments or CI history of real PRs. No repo measures annotator agreement either. The DESIGN claim that "no framework has this layer" holds for this collection. What the collection does offer:
1. Label-reliability engineering: repeated gold validation, flaky policies, error kept separate from 0, and judges run in both orders.
2. Evidence-bound labels, where a label must agree with the executed evidence or it is refused.
3. Typed per-step failure categories (NeMo Pivot `StepRewardCategory`).
4. Per-turn incidents with a quoted snippet and a strength.
5. Ways to calibrate a rubric against human tiers.

### 2. Ranked features Crucible M4 should take

1. **Make reliability independent of the mapper's own definitions.** Source: repo2rlenv `quality/loop/runner.py:114-140`, where a label is checked against *separately recorded* evidence and refused on contradiction.
   - Changes: `crucible/src/crucible/signals/reliability.py`.
   - Today `verdict()` scores a signal against facts the mapper already used to type it (see 3.1). Score each type only against evidence the mapper did not read: CI after the step, a revert or hotfix, or the reviewer's later approval of the same lines. Return `None` when only defining evidence exists.
2. **Turn a flake boolean into a flake rate, shared across traces.** Sources: R2E-Gym `README.md:29-38` (10× retry, drop only at 0/10), SWE-rebench `README.md:193-200` (independent pass 2, recorded verdicts), MiMo `parity.md:66-77`.
   - Changes: `packs/coding/src/crucible_pack_coding/signals.py:76-116`, which should use `connectors/ci_logs.py:313 flaky(traces)`, today not wired into M4.
   - Today a check is flaky only if it both passed and failed on the same SHA *in the same PR*. A test known to be flaky elsewhere still yields a -1. Keep a per-check flake rate across the corpus. Set `polarity=0` with `meta.flake_rate` when the rate is above a threshold, and lower that check's reliability prior.
3. **Use a three-state check: pass, fail, invalid (not scored).** Sources: MiMo `README.md:94`, openai-math `tests/grade.py:18-20`, fineenvs `multi_harness.py:78-85`, Scale-SWE categories `README.md:28-38`.
   - Changes: the coding `signals.py` `IGNORED_CI` path, and `AgentRunSignalMapper` (`signals.py:136-159`, where `reward < 1` becomes -1 even when the run errored).
   - Infrastructure errors become `meta.invalid=True` with `polarity=0` and a typed reason (`infra / timeout / cancelled`), never -1.
4. **Typed per-step failure categories for pivots.** Source: NeMo `StepRewardCategory`, `REF/adithya-s-k-fineenvs/tooling/hf-rl-explorer/app/vendor/nemo_gym/verification_utils.py:60-75`, `.../app/envs/nemogym.py:13-15`.
   - Changes: `crucible/src/crucible/signals/pivots.py`.
   - A pivot should record *what kind* of wrong (wrong tool, wrong argument value, missing call). Diff the graded step's action against the corrective signal's fix (`meta.fix` / `fixed_by_seq`), so M6 and the forge get typed (rejected, chosen) pairs.
5. **Gate integrity in the repo2rlenv style.**
   - Sources: `quality/report.py:41-51` (a completed check needs evidence), `quality/labels.py:56-139` (a label is bound to hashed evidence).
   - Changes: `crucible/src/crucible/signals/gate.py` and the `labels_*.json` format.
   - Store each hand label with the trace content hash it was made against, and refuse to score against a rebuilt trace whose hash changed. Today `m4/gate.py:25` rebuilds the traces from GitHub by default.
6. **Held-out label split plus a significance check.** Sources: termgrade `README.md:114-123` (`heldout120`), autoresearch `prepare.py:43-44` (pinned val shard), fineenvs `split_tasks.py:1-20`.
   - Changes: `packs/coding/src/crucible_pack_coding/m4/` (only `labels_dev.json` exists) and `signals/gate.py`, which should report a binomial lower bound and not only the point estimate.
7. **Per-step incident snippets for text signals.** Source: spiral_bench `spiral_bench.py:139-198`, `utils.py:216-276` (`[snippet, strength]` per behaviour per chunk, polarity, cap).
   - Changes: the `Signal` schema (`crucible/src/crucible/core/schema/signal.py`), plus the coding and toy mappers.
   - Today a review comment collapses to one type. Add `meta.evidence_span` (the quoted cue that triggered the `REQUEST`/`PRAISE` regex) and a strength (nit vs bug). The gate's error list can then show *why* a type was chosen, and M6 can weight a nit below a bug.
8. **Calibrate any judge or rubric-derived signal against human tiers before use, and run judges in both orders.** Sources: watercolour `envs/watercolour/core/quality.py:1-33`, `pairwise_judge.py:11-25, 440-453`; reward_bench `utils_v2.py:35-39`; uq `uq.py:194-235`.
   - Changes: `crucible/src/crucible/signals/reliability.py`. Add a `calibrate(signal_type, hand_labels)` step that sets the Beta prior from hand-label agreement, not a fixed (1,1)/(3,1)/(4,1).
   - The coding mapper's `intent()` regex is in effect a judge and should be calibrated the same way.
9. **Weighting by redundancy and variance.** Source: repo2rlenv `_pr_diff_verifier.py:405-430` (a zero-variance component gets weight 0; components correlated at 0.85 are de-duplicated).
   - Changes: `reliability.py` / M6 compose.
   - An APPROVED review and a praise comment by the same reviewer on the same commit, or CI reruns of one check, are one piece of evidence and should not count twice.
10. **Experiment ledger as a trace family, with the `target` signal.** Sources: autoresearch `program.md:66-110` (keep / discard / crash per commit; delta vs last kept), NatureBench `scoring.py:96-111` (improvement over published SOTA).
    - Changes: a new pack mapper. `taxonomy.py` already has `target`, but no mapper emits it (see 3.6).
    - Caution: autoresearch keeps any strict improvement from a single noisy run (`program.md:103-104`). A keep/discard derived from one measurement needs a noise band before it counts as `approval` or `revert`.
11. **Do not treat revert, backport, cherry-pick or branch-sync PRs as ordinary work.** Source: repo2rlenv `pipelines/pr_runtime.py:318-335`.
    - Changes: `packs/coding/src/crucible_pack_coding/outcomes.py` and `connectors/github_pr.py:40`.
    - `FIXLIKE` matches `revert|fix|bug|wrong…` on any later commit that touches PR lines. That labels the PR `bad` with no reliability check (see 3.5).

### 3. Crucible M4 defects and gaps vs the spec

1. **Reliability is circular for most types (defect).**
   - `signals/reliability.py:52-53`: `correction` and `suggestion_accepted` are "confirmed" unless (`revert` and outcome good), so for them the result is always True. The report shows correction 72/0 and suggestion_accepted 25/0 (`docs/modules/reports/m4_gate_coding_dev.json`).
   - `rejection` in the coding pack is *defined* as "requested and not acted on" (`packs/coding/.../signals.py:93`, where `acted_on=False`). `verdict()` then marks every rejection in a PR that ended `good` as contradicted (`reliability.py:57-58`), which gives 0/21 and a mean of 0.043.
   - So these numbers describe the mapper's definitions, not how well each signal agrees with independent later evidence. M6 would weight rejections at about 0.04 on that basis.
   - The estimate also runs on the same 14 traces the gate scores (`m4/gate.py:28-30`), i.e. in-sample, with no held-out evidence.
2. **The toy pack has no working M4 path, and its gate fails (defect, reproduced in memory).**
   - The toy mapper is registered for family `toy/support_ticket` (`packs/_toy/src/crucible_pack_toy/__init__.py:20`), but toy traces carry `toy/helpdesk_ticket` (`m56/pipeline.py:46`). `mapper_for()` returns None, so `extract()` raises `LookupError`.
   - No toy `outcome_labeler` is registered. The outcome rule lives as a plain function in `m56/pipeline.py:72-84`.
   - No toy M4 gate runner or report exists.
   - Run with the mapper passed in explicitly against `m4/labels_test.json`, the result is **type accuracy 0.869 (< 0.9, FAIL)** and attribution precision 0.909.
   - Confusion: `outcome→check_result` ×4 (the guideline labels CSAT as `outcome`, the mapper emits `check_result`), `outcome→none` ×1, `rejection→none` ×3 and `approval→none` ×3. The guideline maps customer replies to rejection or approval, and the mapper has no customer-reply rule (`packs/_toy/.../signals.py:28-29`).
3. **The coding gate passes on a dev split only, with labels the builder iterated on, and no `bad` outcomes.**
   - `labels_dev.json` has `split: dev`, `labeled_by: "Claude (the builder)… Not a human expert"`, and "4 labels revised".
   - Outcomes are 11 good and 3 unknown, with 0 bad. The revert, hotfix and closed-unmerged paths of `outcomes.py` are therefore never tested by the ≥0.95 outcome criterion.
   - There is no test split, while the spec asks for hand labels. All metrics are 1.0.
4. **Gate attribution misses false attributions (defect).** `signals/gate.py:64` scores precision only when *both* prediction and label have grades. A signal that grades a step where the label says `grades: null` (the line predates the PR) is never counted as a precision error. A predicted signal with an empty `grades` where the label names a step is not counted against recall either. Type accuracy also takes only the first signal per `source_event` (`gate.py:56`), so extra signals on the same event are invisible.
5. **The outcome label rests on an unvalidated hotfix heuristic.** `outcomes.py:19-23` marks a PR `bad` when any later commit matching `FIXLIKE` (`connectors/github_pr.py:40`, which includes `fix|bug|wrong|revert`) touches PR lines within 30 days. That is SZZ-style evidence with known high false-positive rates (refactors, "fix typo"), and no reliability is estimated for it. `closed_unmerged → bad` (`outcomes.py:24-25`) also treats PRs that were superseded, duplicates or closed as stale as failures. repo2rlenv's typed outcomes (`task_defect / infrastructure_failure / insufficient_evidence`) show the missing middle states.
6. **Taxonomy types that no mapper emits.** No mapper emits `target`, `interrupt` or `outcome`. The spec's coding list includes "perf targets", and DESIGN §5.2 has rows for "benchmark numbers in the PR / CI" and "user interrupt / manual edit after the agent finished". There is also no mapper for the `ci_logs` connector's traces, so `extract()` raises on them, and `connectors/ci_logs.py:313 flaky()` is unused by M4.
7. **Toy CSAT signal grades nothing.** `packs/_toy/.../signals.py:53-60` emits `check_result` with no target and no `source`-linked object, so it gets no grades and is always `unscored` in reliability. The module docstring calls it trace-level, but `check_result` is a step type (`taxonomy.py:36`).
8. **`AgentRunSignalMapper` turns any `reward < 1` into -1** (`packs/coding/.../signals.py:153-156`). A run that errored or timed out (an infrastructure failure) becomes a failed gate. See feature 3.
9. **Spec drift.**
   - ARCHITECTURE M4 lists `labels.py`, but labelers live in `extract.py`.
   - Pivots count `revert` as corrective (`pivots.py:13`). A revert gives no "chosen" action, so the spec's "graded wrong and then corrected" (a (wrong, fix) pair) does not hold for it. Mark revert pivots as `fix_known=False`.

### 3. Crucible M4 defects and gaps versus the spec (new unless marked)

**G1 [H][ran] A mini-swe-agent rejection, takeover or new-task message is typed `user_message`, not a signal source.**
- *Where:* `C/core/agent_events.py:24-27` (`INTERRUPT`, `REJECTED`) and `user_type` `:103-104`.
- *Probe:* `crucible/.venv` against mini's exact strings:

  | String | `user_type` | `REJECTED` |
  |---|---|---|
  | "Interrupted by user: …" | `interrupt` | False |
  | "Commands not executed. The user rejected your commands with the following message: no" | `user_message` | False |
  | "Commands not executed. Switching to human mode" | `user_message` | False |
  | "The user added a new task: …" | `user_message` | False |
  | "User command: …" (a human-executed action) | `user_message` | False |

- *Why it fails:* `REJECTED` only knows the Claude Code / Codex phrasings and only checks `tool_result` text (`chat_messages.py:87`). Mini puts the rejection in a **user** message.
- *Effect:* the spec's taxonomy types `interrupt`, `rejection` and `correction` (human takeover) are lost for DeepSWE-style mini-swe-agent runs.
- *Fix:* read `extra.interrupt_type` (`UserInterruption`, `UserRejection`, `UserNewTask`) when present; extend the regexes as a fallback.

**G2 [H][read] Last-writer attribution cannot grade a rejected command.**
- *Why it fails:* a rejected proposal was never executed, so it has no `writes`. `attribute` (`C/signals/attribute.py:31-43`) grades the last event that *wrote* the target object. That is an earlier, unrelated step, or nothing.
- *Study A16* proposes "signals targeting `writes[0]`, attributed by last writer". For mini-swe-agent `UserRejection`, and for Claude Code permission denials, that grades the wrong step.
- *Spec:* ARCHITECTURE says the generic rule is "the event that last wrote the object the signal is about". The object here is *the proposed call*.
- *Fix:* for `interrupt` and `rejection`, `grades = [the assistant/tool_call event the user message answers]` (`reply_to`, or the immediately preceding call). Set it in the mapper so `attribute` leaves it alone.

**G3 [M][read] Human-executed actions are not attributed to a human actor.**
- In mini's human mode the command is a `user` message with `extra.actions`, executed in the sandbox (`interactive.py:58-70`). `chat_messages.py:61-62` records it as `actor="user"` text with no `writes`.
- *Effect:*
  - a later signal on the files it touched grades the agent's earlier write, not the human's;
  - the (agent proposal → human command) pair, the clearest pivot in such a trace, is never formed. `C/signals/pivots.py:13-23` only pairs `correction` / `suggestion_accepted` / `revert` signals.
- *Spec:* "who-wrote-what" via `exclude_actors` exists (`attribute.py:19-28`), but needs the writes recorded.

**G4 [H][read] The infra-failure classification in M3 never reaches M4.**
- *Where:*
  - `CP/connectors/ci_logs.py:286-300` sets `failure_kind = "infra"` and outcome `unknown`;
  - `ci_logs.flaky()` (`:313-320`) is documented as "listed so M4 can discount them" (`:19-20`);
  - `coding/ci_run` has no signal mapper (`crucible/packs/coding/pack.yaml:30`, `label: false`; `CP/__init__.py:26-28` registers only `coding/pull_request` and `coding/agent_run`);
  - the PR mapper scores every GitHub check `failure` / `timed_out` as −1 (`CP/signals.py:44,108-116`) with no infra test.
- *Evidence:* `grep` finds no caller of `flaky(`.
- *Effect:* runner OOM or network failures become −1 `check_result`. The reliability rule then *confirms* them whenever the PR ends `bad` (`reliability.py:54-57`).
- *Contrast:* MiMo masks and DeepSWE uses a −1 sentinel, so neither trains on a false 0.

**G5 [M][read] Agent-run outcome ignores sentinels and infra.**
- *Where:* `CP/connectors/agent_runs.py:91-92` labels `bad` whenever `reward < 1.0`; `AgentRunSignalMapper` emits −1 for any `reward < 1` (`CP/signals.py:153-156`).

### 3. Crucible M4 defects / gaps found while comparing

1. **`dpo_pivots` pairs a "chosen" that was produced at a different state.** `studio/datasets.py:170-178` takes `chosen = msgs[turn_of_seq[fix.seq]]`, the fix message at a *later* turn (after the wrong step and the reviewer's feedback). `dpo_pivots` (:268-273) pairs it with `prompt = messages[:i]`, the state *before* the wrong step. ### 2. Ranked features Crucible M4 should take

1. **Signal-marked step credit with per-sign mass conservation (PORT).**
   Source: `xiaomimimo-verl/verl/trainer/ppo/signed_rebalance.py:46-215`, strategies `verl/trainer/config/algorithm.py:70-100`, `v1/trainer_base.py:102-163`, hit construction `arvo_penalties.py:146-188`.
   Crucible: new `crucible/src/crucible/credit/operators/signal_marks.py` (or inside `credit/compose.py`), `credit/steps.py` (add `StepRow.marks: list[{signal_id,type,polarity,reliability}]`), `core/schema/reward.py:63` (`StepRow`).
   Why: today M4 signals never reach a step's credit. `compose.py` builds per-turn credit from ΔΦ only, and its docstring already cites the reason a whole-turn negative shift is harmful (`compose.py:21`). MiMo's operator is the tested answer to exactly that. Map it like this. A negative step signal (rejection, correction, revert, violation, interrupt, failing check) on step g marks g's tokens with κ = 1 + λ·reliability. Positive rows lose those tokens' credit and negative rows are punished harder, with each sign's mass conserved. Polarity-0 signals (flaky CI) and `is_infra`-style rows get no mark (MiMo skips infra rows, `arvo_penalties.py:152`). Pick the strategy per signal type from M4 reliability. Use `monitor` until the type has n ≥ N scored verdicts and mean ≥ τ, then switch to `adv_signed`. That makes reliability something the trainer uses, not just a number in a report.

2. **Reliability → noise-robust preference export (PATTERN).**
   Source: TRL robust DPO `dpo_trainer.py:1407-1410` (ε<0.5 check 803-806); cDPO `openrlhf/models/loss.py:354-358`.
   Crucible: `crucible/src/crucible/studio/datasets.py:268` `dpo_pivots` (and `signals/pivots.py`).
   Why: a correction pivot is a preference label whose flip rate is about 1 − reliability(type). Put `reliability` and `label_noise = 1 − reliability` on every pivot row. TRL's ε is global, so split the pivot export into reliability buckets, one file per ε, and drop pairs whose ε ≥ 0.5. A pair at that level has no direction. Today pivots carry no reliability at all.

3. **Step-granular KTO rows from approval/rejection (PATTERN).**
   Source: TRL `kto_config.py:81-85`, imbalance guard `kto_trainer.py:1140-1160`.
   Crucible: `studio/datasets.py:278` `kto_rows`.
   Why: KTO is the native loss for *unpaired* expert feedback. Most M4 signals are unpaired: a rejection without a fix, an approval, a failing check. `kto_rows` only emits whole-trajectory rows labelled by outcome. Add one row per graded policy step: the prompt is the history before the step, the completion is the step, the label is polarity > 0, and the row is filtered by reliability. Emit the recommended `desirable_weight` / `undesirable_weight` from the counts, because negatives will dominate.

4. **Text feedback as dense credit, SDPO rows (PATTERN).**
   Source: TRL `sdpo_trainer.py:258-291, 834-877`, `sdpo_config.py:89-105`.
   Crucible: `studio/datasets.py` (new `sdpo_rows`), sourcing `Signal.text` and `meta["fix"]` from `signals/extract.py` output.
   Why: rejection and correction signals carry exactly the reviewer text SDPO wants as `privileged_context`. This credits the wrong step even when no (wrong, fixed) pair exists. Those are the `pivots_unpaired` cases (`datasets.py:55`), which are dropped today.

5. **Model-attributable filter and span-coverage validation (PORT).**
   Source: `arvo_penalties.py:152-172` (skip `is_infra` and require spans to cover exactly the generated tokens), `recipes/arvo/trajectory_metadata.py:22-38`; prime-rl `algo/routing.py:17-40` (length-checked routing).
   Crucible: `signals/attribute.py` (a signal that grades a step not authored by the policy, or by infra, should get `meta["attributable"]=False`), `credit/steps.py` (`rows_for` should check that the marked steps map onto `call_id` token spans).
   Why: `attribute()` can attribute a signal to any event's writer, including system or CI events. Credit must only land on the policy's own sampled tokens.

6. **Unscorable is not 0 in reliability and outcome labels (PATTERN, confirmation).**
   Source: TRL `grpo_trainer.py:2685-2741`; MiMo `eval_mode.py:30-40`, `judges.py:51-77`. Anti-pattern: rLLM `llm_judge.py:72-79`.
   Crucible: `signals/reliability.py` already returns `None` and counts it as unscored. Keep that. Also add a rule to `OutcomeLabeler` that "unknown" (`outcomes.py:27,30`) never becomes 0 downstream. `kto_rows` already skips it; `dpo_best_vs_worst` uses `reward`. If an LLM-judge mapper is ever added (taxonomy candidates), a parse failure must yield no signal, never a default polarity.

7. **Per-role / per-actor baselines (PATTERN).**
   Source: prime-rl `algo/rae.py:16-43`, `algo/hierarchical_grpo.py:33-42`; rLLM `advantage.py:190-229`.
   Crucible: `credit/compose.py` (group statistics keyed by `StepRow.actor` role), plus `Signal.actor` and the role of the graded event's actor.
   Why: multi-seat Worlds (M2) and reviewer-vs-author traces need per-role baselines. An approval by a reviewer should credit the author's step, not the reviewer's. Mixing roles in one baseline is the failure RAE documents.

8. **As-known-at stamping for late evidence (PATTERN).**
   Source: prime-rl `orchestrator/annotations.py:1-40`.
   Crucible: `signals/reliability.py` and `core/schema/signal.py` (add `known_at`).
   Why: reverts and hotfixes arrive up to 30 days later. Reliability, and any training row built from it, should only use evidence known before the cut-off. This also fixes defect D4 below.

9. **Per-signal-type channel normalization (PATTERN, M6-side).**
   Source: verl GDPO `core_algos.py:361-468`; TRL `normalize_then_sum` `grpo_trainer.py:2719-2726`.
   Crucible: `credit/compose.py`.
   Why: when several signal types become reward components, a frequent type (CI checks) should not drown a rare, high-reliability one (revert).

10. **Reliability-weighted sampling (PATTERN, low).** Source: verl PF-PPO `core_algos.py:2254-2331`. Crucible: `studio/datasets.py` curation. Why: sample training rows in proportion to signal reliability instead of a hard threshold.

Not recommended: rLLM `per_step` mode, which needs equal step counts (`transform.py:96-100`). SkyRL step-wise broadcast, which drops per-step rewards (`trainer.py:1214-1217`). Upstream verl `turn_scores`, a dead field. All three show that per-turn signals sent as *rewards* get dropped silently. Crucible's per-step credit should travel as precomputed advantages (rLLM `Step.advantage`, prime-rl `assign_advantages`), and each adapter should assert that the per-step credit was used.

### 3. Crucible M4 defects and gaps found

- **D1. Reliability never reaches anything (gap, high).** `estimate`/`apply` (`crucible/src/crucible/signals/reliability.py:70-86`) are called only in the coding gate script (`crucible/packs/coding/src/crucible_pack_coding/m4/gate.py:13, 28-29`). `extract()` (`signals/extract.py:52-69`), `studio/label.py:102`, `cli/studio.py:138` and `forge/derive.py:38` never set it, so `Signal.reliability` is always `None` in production. A grep for `.reliability` in `credit/`, `studio/datasets.py` and `workflow/` finds no reader. The docstring promise at `reliability.py:14` ("so credit assignment (M6) can weigh evidence") is unmet. Fix: a reliability table persisted per pack/family, applied in `extract` or `label`, and consumed per features 1–3.
- **D2. AI-reviewer signals pooled with human ones (defect).** `github_pr.py:197` says an AI reviewer's "signals are kept apart from human experts' in reliability", and the mapper writes `meta["automated"]` (`crucible_pack_coding/signals.py:71-74`). But `estimate` keys only by `s.type` (`reliability.py:73`). The docstring's "per type (per family)" (`reliability.py:13`) is not implemented either. Copilot rejections and human rejections share one Beta posterior. Fix: key by `(family, type, automated|actor kind)`. MiMo's model-attributable split and prime-rl's per-agent baselines are the same idea.
- **D3. Circular verdicts (defect).** The coding labeler sets the outcome to `bad` *because of* the revert or hotfix events (`crucible_pack_coding/outcomes.py:18-23`), and those same events are emitted as `revert` / `correction` signals. `verdict()` then confirms every LATER_EVIDENCE signal unless the outcome is good (`reliability.py:52-53`), so revert reliability is 1 by construction. It also confirms *every* negative signal on any step once the outcome is `bad` (`reliability.py:56`) and contradicts every approval (`reliability.py:64`), even when the revert touched other commits. Step-local evidence is already available, since revert and hotfix `grades` are the touched commits (`signals.py:118-122`), but it is unused. Fix: confirm or contradict on the graded step first (a later corrective signal grading the same seq, or `acted_on`), use the trace outcome only as a weaker fallback, and exclude a signal's own event from the outcome evidence it is scored against.
- **D4. In-sample, not time-split, estimation (gap).** The gate estimates reliability on the very traces it scores (`m4/gate.py:28-29`). There is no held-out or time split, unlike M6's validity gate. A signal's own verdict feeds the reliability written back onto it. Fix: leave-one-trace-out or an as-known-at cut-off (feature 8).
- **D5. Gate scores one signal per event (minor).** `signals/gate.py:56` takes the first signal whose `source_event` matches. `AgentRunSignalMapper` emits several `check_result` signals per `final_patch` seq (`crucible_pack_coding/signals.py:141-158`), so all but one are never scored for type or attribution.
- **D6. No signal channel in the dense rows (gap).** `StepRow` (`crucible/src/crucible/core/schema/reward.py:63-75`) has `violations` but no signal marks, and `compose.py`'s `delta` mode uses ΔΦ only. So M4 → M6 has no path except C2 `defect_to_check` (`credit/operators/defect_to_check.py:1-14`), which uses only corrections with a diff. Feature 1 closes this.
- **D7. Preference exports ignore signal quality (gap).** `dpo_pivots` (`studio/datasets.py:268-276`) carries no reliability or label-noise field, and `kto_rows` (`datasets.py:278-287`) is trajectory-level only. Rejection, approval and check signals never become training rows (features 2–4).
