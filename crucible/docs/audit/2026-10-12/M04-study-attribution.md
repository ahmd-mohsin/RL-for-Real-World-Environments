## 2. Defect candidates

Severity: P0 = silently corrupts signals, labels or provenance in normal use; P1 = corrupts in a common case or leaves a spec promise unmet; P2 = edge case or hygiene.

### Matching and the last-writer rule (`C/signals/attribute.py`)

**A1 [P1][ran] Absolute and relative paths never match.** `_covers` compares strings. Claude Code / OpenHands write `file:/home/u/repo/src/a.py` (`writes_of` keeps the tool's `file_path`), GitHub review targets and `final_patch` use `file:src/a.py`. Input (p1): event 0 writes `["file:/home/u/repo/src/a.py"]`, correction at seq 1 targets `file:src/a.py`. Observed: `grades []`. Same for `file:./a.py` vs `file:a.py` (`sed -i ... ./a.py` -> `file:./a.py`), and `cd pkg && sed -i ... a.py` records `file:a.py` (cwd ignored). Expected: grades `[0]`. Fix: canonical object keys at write time (`posixpath.normpath`, strip the workspace root recorded on the trace, keep the cwd of `cd X &&`), and in `_covers` fall back to NeMo's suffix rule (`swe_pivot/app.py:198-207`) only when both sides are paths and one is absolute.

**A2 [P1][ran] `.` is both a field separator and a file-extension character.** `_covers("file:a", "file:a.py")`, `("file:README", "file:README.md")`, `("file:a.py", "file:a.py.bak")` and `("file:a.py", "file:a")` are all `True`. Input (p2): seq 0 `sed -i s/x/y/ a.py` (writes `file:a.py`), seq 1 `cp a.py a.py.bak` (writes `file:a.py.bak`), correction at seq 2 on `file:a.py`. Observed: `grades [1]`, the backup copy. Also (p1) a write to `file:setup` steals the grade for `file:setup.py`. Expected: `[0]`. Fix: scheme-aware covering: for `file:` objects use `/` as the only hierarchy separator; keep `.`-field covering for record objects (`ticket:T1.status`). Non-defects checked: `ticket:4` vs `ticket:42` and `a.py` vs `a.pyc` do not match.

**A3 [P1][ran] The App is ignored: peers in separate workspaces credit each other.** `last_writer` reads only `data.writes` (bare `file:a.py`); the App is on `event.target.app` (`world.py:994`) and `signal.target.app`. Input (p1): peer_a writes `file:a.py` in `ws_a` (seq 0), peer_b writes `file:a.py` in `ws_b` (seq 1), failing check at seq 2 targets `app=ws_a, object=file:a.py`. Observed: `grades [1]` (peer_b). Expected: `[0]`. This is the P28 multi-agent case. Fix: qualify writes with the App (`ws_a/file:a.py` or a `{app, object}` pair) and match the App when the signal names one.

**A4 [P2][ran] Directory moves and other common writes are invisible.** `writes_of("bash", "git mv src lib")`, `rm a.py`, `git apply fix.patch`, and a `python - <<EOF open('a.py','w')` heredoc all return `[]`; a recorded `file:lib` would not cover `file:lib/a.py` either (`/` is not a separator in `_covers`). Input (p1): seq 1 writes `["file:lib"]`, signal on `file:lib/a.py`. Observed `[]`, expected `[1]`. Fix: `/` as a hierarchy separator for `file:` (A2), add `rm`/`git mv`/`git apply`/`patch` to `shell_writes`, and fall back to the M5 replay state diff (`C/workflow/logstate.py`, file-effect replay) when the text parser finds nothing.

**A5 [P1][ran] Seq order is not time order for ATIF subagents.** `atif_import.walk` appends every subagent trajectory after the whole main trajectory (`atif_import.py:103-106`). Input (p4): main steps at 10:00, 10:00:30 (`Task` call), 10:05 (user: "that change to a.py is wrong"); subagent Edit of `a.py` at 10:02. Imported seqs: user correction = 3, subagent Edit = 5. Observed: correction `grades []`. Expected: the subagent Edit (seq 5). The `Task` call that delegated it (seq 1) records no writes either, and the `subagent_trajectory_ref` on its result (Harbor `observation_result.py:30`) is dropped, so neither the subagent nor its parent can be credited, which is exactly P28's "the agent, or sub-agent, that made the change". Fix: splice each subagent's events after the call whose result references it (by `trajectory_id`), or order by `(time, seq)`; record `data.delegated_to` on the `Task` call and let `last_writer` optionally credit the delegating call too.

**A6 [P0][ran] World App tools record no writes, so enterprise Worlds have no step credit.** `writes_of` knows file editors and shells only. Input (p4): `tickets.update_ticket`, `erp.approve_invoice`, `mail.send` -> `[]`; `ws.write_file` -> `['file:a.py']`. `World.to_trace` (`world.py:992-995`) therefore leaves every ticket / ERP / AP-invoice action without `writes`, and a later violation on `ticket:T1.refund` grades nothing. Toy and AP logs ingested by `file_drop` do carry writes (row column), so recorded logs attribute but World episodes of the same workflow do not. DESIGN P28 promises credit for any edit, and the fix table (`DESIGN.md:2914`, "World traces recorded no `writes` ... `writes` per edit call; fixed") covers file edit calls only. Fix: Apps declare their writes: each App tool returns or declares the objects it changed (`App.writes(call, result)`, or the store diff the App already computes), and `to_trace` records them; `writes_of` stays the fallback for opaque tools.

**A7 [P2][ran] `exclude_self` with an anonymous source credits that same anonymous editor.** `attribute.py:39` excludes `{src.actor}` only when it is truthy. Input (p1): agent writes `ticket:T1.resolution` (seq 0), an actor-less event rewrites it (seq 1), an actor-less `supervisor_edit` with `exclude_self` at seq 2. Observed `grades [1]`. Expected: `[0]`, or no grade with a reason. Fix: when `exclude_self` is set and the actor is unknown, exclude events with `actor is None` too, or refuse to attribute and record why.

**A8 [P2][ran] A reviewer's own write can be the graded step.** Input (p1): author writes `file:a.py` (0), reviewer pushes a fixup commit to it (1), reviewer comments at 2 (rejection, no `exclude_self`). Observed `grades [1]`, a rejection of the reviewer's own commit. Expected: `[0]`. Fix: by default exclude writes by the signal's own actor for negative step signals; packs opt out.

**A9 [P2][ran] "Not attributable" and "trace-level" look the same.** A step signal whose object nobody wrote, or with `source_event=None`, comes back with `grades []` and empty `meta` (p1). `reliability.verdict` then returns `None` (`reliability.py:48`), so the signal silently drops out of reliability and pivots. Fix: record `meta.attribution = "unattributed"` with the reason (`no_writer`, `no_source_event`, `no_target`), as verifiers distinguishes `None` from zero credit (`verifiers/v1/trace.py:259-267`); report the unattributed share in the M4 gate.

**A10 [P2] Toy escalations and SLA breaches credit the router, not the person.** Over the 24 toy logs (p3): `escalation` grades `assigned` by `queue` 4/4, `sla_breach` grades `assigned` by `queue` 3/3. The hand labels agree (`TP/m4/labels_test.json`), so precision is fine, but the credit lands on a system actor that is never a policy, so these signals never reach a trainable step. Fix: let the mapper name the responsible role (`meta.responsible = "assignee"`) and attribute to the assignee's last write or turn; keep the router credit as a separate grade.

### Extraction plumbing (`C/signals/extract.py`)

**A11 [P0][ran] Signal ids are keyed on seq, so a grown source changes every id, and the M3 carry-over keeps ids that no longer match the rule.** `signal_id(trace, type, source_event)`; seqs are positions. Input (p3): toy case T1003 extracted (v1), then the same rows plus one earlier `note` row (v2). Observed: v1 ids `sig_62a4…, sig_3642…, sig_36e0…`, v2 ids `sig_ed8d…, sig_4acd…, sig_c91a…`, 0 kept. Through `TraceStore.put` (M3 carry-over, `trace_store.py:44-66`) the head keeps the v1 ids with remapped `source_event` 5, 6, 7, while a fresh extract of that head gives different ids for the same `source_event`s. Every downstream reference to a signal id breaks silently: forge provenance and the A8 "trap signal resolves" check (`CP/forge/derive.py:394`, `TP/forge/hindsight.py:166-182`), milestone provenance (`C/workflow/milestones/mine.py:205-208`), C2 check ids (`C/credit/operators/defect_to_check.py:54`). Fix: key ids on the stable event identity the store already uses (`data.row_id`, else `(time, type, actor, text)`, `trace_store.py:39-42` (`_identity`)) plus the mapper's `extra`, not on seq.

**A12 [P1][ran] Re-extraction drops signals already on the trace and their reliability.** `extract` sets `signals` to the mapper's output (`extract.py:66`). Input (p2): trace with a hand / carried `interrupt` signal and a `rejection` with `reliability=0.83`; mapper returns the same `rejection`. Observed after: one signal, `reliability None`; the `interrupt` is gone. `outcome.details.probes` survives, `pivots` is recomputed. This also defeats M3's carry-over (A11) and any signal not produced by the current mapper (an M4 gate correction, a hand label). Fix: merge by id like verifiers' idempotent edge merge (`trace.py:582-591`): mapper output replaces signals with the same id, others are kept unless tagged `meta.by_mapper`; re-apply reliability when the table is available.

**A13 [P1][ran] Extract output is never validated, so a bad mapper poisons the store and fails later at load.** `model_copy` skips `Trace._check`. Input (p2): mapper returns `grades [999]` (unknown seq) and an approval at `source_event 0` grading seq 1 (a step after the signal). Observed: `extract` succeeds; the future grade passes even a full validation; the unknown grade fails only when the dumped trace is read back (`ValidationError: signal sig_x grades unknown events [999]`), i.e. in whichever later stage loads it. Fix: end `extract` with `Trace.model_validate(out.model_dump())` and add two checks: every grade exists, and every grade is `< source_event` unless the signal is a check on the state it grades (`check_result`). prime-rl raises on misaligned credit for the same reason (`routing.py:21-34`).

**A14 [P2][ran] Polarity is not checked against the taxonomy.** Input (p2): mapper emits `suggestion_accepted` with `polarity +1` ("accepted = good"). Observed: accepted, kept as `+1`, and `pivots` is `{}` because `pivots` needs `polarity < 0`. The taxonomy fixes it at -1 (`taxonomy.py:34`). Fix: for types whose taxonomy polarity is non-zero, reject or coerce a mismatched polarity in `extract`.

**A15 [P2][ran] A duplicate id aborts the whole batch.** Input (p2): a mapper emits two `check_result` signals for one `ci_run` event (lint, tests) without `extra`. Observed: `ValueError: duplicate signal id …`. `studio.label` (`label.py:118-122`), `forge/derive.run_signals` and `forge/hindsight.case_signals` call `extract` in a loop without isolation, so one trace stops the run. Fix: error message names the trace and type, callers isolate per trace (as M3 ingest does) and count failures.

**A16 [P1][ran] Agent-session families have no mapper, so DESIGN §5.2's session rows produce no signals.** `mapper_for("coding/construction_session")` is `None`; the ATIF / capture / OTel / chat importers set `family` from the source and no core mapper handles them. Input (p3): a Claude Code trace with a `tool_result` `rejected: True` and an `interrupt` event. Observed: `LookupError: no signal_mapper registered for family 'coding/construction_session'`. The importers already mark `interrupt` and `rejected` (`atif_import.py:74,101`, `capture_proxy.py:434`), and the taxonomy has `interrupt`, but nothing maps them: "User interrupt or rejected edit -> negative on that tool call" and "Manual edit after the agent finished -> (agent output, expert fix) pair" (DESIGN §5.2) have no implementation. World episodes (`family = spec.world`) have no mapper either, so A6's writes would have no consumer. Fix: a core generic `AgentSessionMapper` registered as the fallback for any family (interrupt / rejected / user edit of a file the agent wrote -> signals targeting `writes[0]`, attributed by last writer); packs override it by family.

**A17 [P1][ran] The toy M4 hand labels name a family no mapper serves.** `TP/m4/labels_test.json` (84 events) uses `toy/helpdesk_ticket:*`; the toy mapper is registered for `toy/support_ticket`. Observed (p4): `{'toy/helpdesk_ticket': None}`; no code loads the file (only the coding pack has `m4/gate.py`). The toy half of the ARCHITECTURE M4 exit gate ("50 hand-labeled events per pack") is therefore not run. Fix: register the mapper for both names or rename, and add a toy `m4/gate.py` mirroring `CP/m4/gate.py`.

**A18 [P1][ran] A contaminated green agent run emits a positive check signal.** `AgentRunSignalMapper` (`CP/signals.py:152-155`) emits `check_result +1` whenever `reward >= 1`, ignoring `details.contaminated` that `agent_runs.py:87-89` sets when an answer-key probe was exposed. Input (p4): `reward 1.0, contaminated True`, label `unknown`. Observed: `[('check_result', 1, [1], 'hidden verifier reward 1.0')]`. Expected: no positive signal (P27: a green score reached through the answer key is never trusted); emit a `violation` on the probing call instead. The same mapper grades only the synthetic `final_patch` event, never the calls that wrote the failing gate's files, so per-call credit is lost even when `writes` exist (P2).

**A19 [P2] Lookup details.** Case matters (`Coding/pull_request` -> no mapper) and `extract` raises `LookupError` when a family has a labeler but no mapper, so a labeler-only family cannot be labeled through `extract`. The `/` boundary is correct (`coding/pull_request_v2` does not match, `coding/pull_request/v2` does; p2). Fix: lowercase families at ingest; run the labeler and `mark_pivots` even when the mapper is missing, with `signals=[]`.

### Decision points (`C/signals/pivots.py`, `C/studio/datasets.py`)

**A20 [P1][ran] A revert becomes the "chosen" action of a DPO pair.** `CORRECTIVE` includes `revert` (`pivots.py:14`), and `datasets.from_trace` pairs the graded turn with the turn of the signal's source event. Input (p5): agent `refund_issued` (1) and `status_change` (2) in one turn, supervisor flag (3), agent `refund_reversed` (4) graded `[1, 2]` by a revert. Observed: pivot at index 1 with `chosen = refund_reversed`, i.e. "reverse a refund" proposed as the right action at the state before any refund exists. A revert says the step was wrong, not what the right step was. Fix: pair only `correction` / `suggestion_accepted` whose fix is a replacement; keep reverts as pivots for KTO-style negatives (rejected only).

**A21 [P2][ran] Two graded calls in one turn give duplicate DPO rows.** Same input (p5): both graded seqs map to the same turn index, so `dpo_pivots` emits 2 identical rows. NeMo's rule is one model call, one row (`SKILL.md:62-72`). Fix: dedupe pivots by `(turn index, chosen turn)` in `from_trace`; in `pivots()` group grades by model call (`data.step_id` / `call_id`) as well (p3 shows two parallel calls with `step_id 3` become two pivots).

**A22 [P2][ran] A pivot is kept when the outcome contradicts its revert.** Input (p3): trace `good`, `revert -1` on seq 0. Observed: `verdict False` (reliability counts it contradicted), yet `pivots {'0': ['sig_rv']}`. Fix: `pivots` skips signals whose `verdict` is `False`, or carries the verdict so datasets can filter.

**A23 [P2][ran] A revert that touches nothing makes every commit a pivot.** `CodingSignalMapper` grades `touched or final_commits` (`CP/signals.py:120`). Input (p3): 4 commits, a `post_merge_commit` with `is_revert` and `touches_seq []`. Observed: pivots on all of `0..3`. Fix: when `touches_seq` is empty, grade the trace (outcome) instead of every commit, or record `meta.attribution = "all_commits"` and keep it out of pivots.

**A24 [P2] The "chosen" turn is out of state.** Even for a proper correction, `chosen` is the policy's later turn, generated after the reviewer's feedback and the wrong attempt; `prompt = messages[:i]` is the state before the wrong attempt. The pair is valid only when the fix does not depend on the feedback text. NeMo selects pivots from successful trajectories and profiles them with >= 8 local rollouts, keeping mixed-reward states (`SKILL.md:94-110`). Fix: mark the pair `meta.state_shift = true` when other events sit between graded and fix turns, and profile pivots on-policy before training on them.

### Downstream assumption

**A25 [P1] Nothing in M6 reads `grades`.** `grep grades` over `C/credit`, `C/studio`, `CP`, `TP` finds no consumer of step grades except `pivots` and `reliability`; credit comes from pack hooks and Φ (`docs/modules/M06-credit.md`). P28's "credit follows writes ... M4 grades a later signal to the agent, or sub-agent" therefore ends at M4: a negative step signal never lowers the credited step's weight in `datasets.from_trace` (`weights` come only from `phi_by_seq`). Fix: an M6 operator that turns graded negative signals into per-turn penalties (reliability-weighted), in the same per-step slot rllm and SkyRL use (`rllm/trainer/verl/transform.py:55-76`, `skyrl_gym_generator.py:713-719`).

## 4. Where Crucible is stronger

- **A signal-to-step layer at all.** No framework maps human evidence (review, revert, reopen, policy flag) to the step it grades; NeMo-Gym's pivots take the expert action as ground truth and grade by action match, which P12 rejects. Crucible grades states and keeps the action match out of the reward.
- **Pack rule first, generic rule second.** The coding pack attributes by blame within the PR (computed from git by the connector); `attribute` fills only what the pack left empty and stamps `meta.attributed_by`, so the gate can score the two rules separately.
- **Field-level objects.** `ticket:T1.status` vs `ticket:T1.refund` is finer than NeMo's file-path target; record ids do not collide by prefix (`ticket:4` vs `ticket:42`, checked).
- **The signal's own event is excluded** (`seq >= before`), so a reopen that writes the status grades the previous status write, not itself; `exclude_self` covers a supervisor rewriting a reply.
- **Strict event order.** Equal or out-of-order seqs are refused at construction (`trace.py:68-83`); Harbor checks step ids the same way.
- **Corrected pivots.** A pivot needs both the wrong step and the corrective evidence in the trace; NeMo's pivots come from successful trajectories with no negative half. Combined with reliability (per-type Beta), Crucible can weigh how much to trust each pivot, which no framework does.
- **One definition of "write" across sources.** ATIF, capture proxy, OTel, chat, World and file drops share `writes_of`, so a signal attributes the same way whatever recorded the session (once A1/A2 normalize the keys).
- **Family plugins with a `/` boundary**, longest prefix wins, so a pack can specialise `coding/pull_request/ghes` without touching the core and `coding/pull_request_v2` does not match by accident.
