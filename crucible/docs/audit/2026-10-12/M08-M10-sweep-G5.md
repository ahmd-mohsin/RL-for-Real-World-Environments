## Summary

- **M9 cannot accept a single imported task today.** `imports/` (I0–I10) does not exist, no adapter gives a Harbor,
  verifiers-row or NeMo task the acceptance capabilities, and A2 fails any task without a "naive" negative (G1–G3).
  The three HF registry entries are marked `fixed` on synthetic fixtures only (G18).
- **Loading works further than accepting.** All 30 local Harbor sample dirs parse (P1), and NeMo `workplace_assistant`
  rows run and grade (P2, which also reproduces the 13% no-op floor on a real row). No verifiers SWE row can be graded
  (G5).
- **The datasets carry six new defects** beyond P03's D1–D18 (N1–N6, §2.1). The worst: equivalence-tests rewards
  `return undefined_name` 10/10 and a correct implementation 0/10 (N1). NatureBench's validity judge fails open (N3).
- **Three P03 numbers need correcting** (§0): the Multi-SWE "concurrency-only" retest set is mostly one Rust toolchain
  failure; SWE-rebench's "flaky" list is mostly pass-1 failures; and `bash -n` does not catch the D1 no-op oracle.
- **M10 aborts a whole run on one raising harness** and leaves every reservation open (G8, [ran]). Foreign failure
  names fall through to `harness` blame and evade the unknown-blame stop rule (G9, [ran]).
- **Best picks** (§3): an import layer built as acceptance adapters (Harbor in-place, verifiers taskset via its own
  `validate()`/`apply_gold_patch()`, NeMo), with PI Terminal-Lego's 870 task-intrinsic labels as the recall test bed;
  a harness boundary; the validators' failure vocabulary; an 8-rerun concurrency-split flake gate; Karotte's attack
  list in A13; and an iterate-until-clean red-team loop in M8.
